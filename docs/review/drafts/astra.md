**Calculation.** Each reviewer scores independently. Report each weight, anchor and weighted contribution. Round `Σ(weight × score) / 100` to one decimal, then apply the lowest applicable cap. For **every score below 10**, cite `file:line` or a named screenshot, identify the unmet anchor and state expected versus observed behavior. For missing evidence, cite the relevant test, manifest or release inventory and name the missing assertion or artifact. A UI screenshot establishes what the player saw. A captured request establishes what QUEEN received.

**Hard caps**

- **4.0** for unescaped model or site text inserted as HTML, executable remote content, or disclosure of a token to an unauthorized recipient.
- **5.0** for sending a wrong position in a supported core flow. One reproducible wrong ply, branch, root, turn or legal right qualifies. Also cap at **5.0** for a core-flow crash, indefinite wait or dead end with no usable recovery, or a demonstrated Store policy blocker such as an undisclosed transfer.
- **8.9** if position, explanation, Store readiness or release evidence falls below its 9 anchor. A polished panel cannot compensate for an unverified chess.com flow or an incomplete submission packet.

A community outage with working recovery is an expected test case. Judge the extension’s handling of it. The model’s playing strength, GPU requirement and inability to critique arbitrary moves are fixed constraints.

## Part 2 — Target spec

### Read the position the player selected

- **Chess.com.** In finished-game Review and Analysis, bind the active move list to the visible board. Reconstruct figurine SAN, ignore clocks and annotations, and stop at the selected ply. On a selected variation, use its proven ancestry or fall back to the displayed position. Treat a missing selection as the starting position only when the board or page confirms it.
- **Lichess.** In analysis and studies, follow the active `move[p]` path through its ancestors. In finished-round replay, stop at the active move and skip numbering and ellipses. For a custom start, use the PGN root FEN plus the verified line, or the exact current FEN for Best move. Preserve all six FEN fields, including a Black-to-move root and its move number.
- **Board fallback.** Read chess.com square classes and oriented lichess piece coordinates. Ignore animation and drag artifacts. Prefer a current FEN tied to the selected board, then verified history, then an unambiguous last-move pair for turn detection. Unknown turn displays **White to play** and **Black to play**, with Ask disabled until selection. Allow correction of an inferred turn. Home-square occupancy cannot establish castling rights. If history-dependent fields remain uncertain, identify them and offer confirmation or exact FEN entry before sending. Invalid or changing boards get a refresh action.
- **Request boundary.** Re-read on click and bind the request and result to that snapshot. For `1.e4 e5 2.Nf3 Nc6 3.Bc4`, **Explain 3.Bc4** sends the standard root plus `e4 e5 Nf3 Nc6`, with White to move. **Best move for Black** includes `Bc4`. With only a current FEN, send it with empty moves and offer Best move. Enable Explain when the preceding position and played move are known.

### Ask QUEEN and present its answer

- Keep the MV3 architecture small: plain bundled JavaScript, site adapters, a shadow-DOM panel, an options page and a service worker that owns networking. Use the existing `princeton-nlp/queen_pawn-8` model. Default to `boneyland/queen-pawn-8` at `/analyse_position`, with `hugging-apps/queen-pawn-8` at `/analyze` as backup. POST the endpoint-specific argument list, validate `event_id`, then read the corresponding SSE stream. Normalize the two response shapes and discard server-supplied HTML/SVG.
- Give each connection 15 seconds to establish and the whole action 120 seconds including fallback. Heartbeats may update status within that deadline. Try one backup on a transient availability failure. Stop on cancellation, invalid position, game over, authentication failure or explicit quota exhaustion. Honor `Retry-After`. Cancel, close, navigation and superseding requests abort the local fetch/stream, clear timers and invalidate late replies.
- Start inference only on Ask. Coalesce duplicate in-flight requests. Keep a bounded session-memory cache of successful answers, for example 32 entries for 15 minutes, keyed by root FEN, normalized moves, model, server and inference settings. Recompute the played-move comparison for each view. A repeated click or cache hit consumes no additional GPU job. Explain anonymous per-IP quota before a token is needed. Provide settings, read-token setup and a way to clear it.
- Lead with the played move, QUEEN’s choice and whose reasoning follows. Preserve meaningful SAN, move numbers, critical line and evaluation when supplied. Label model judgments as fallible. In the recorded truncated reply, prose recommends `3...Be7` while the server guesses `d5`. Identify `Be7` as inferred from prose and flag the cutoff, or withhold the verdict. A random legal fallback cannot establish agreement. Copy FEN returns the analyzed position.
- Cover launcher, start, selected move, detected/unknown turn, unreadable board, thinking, backup, cancellation, agreement, disagreement, best move, partial answer, error and settings. Name the relevant recovery action: choose a side, refresh, step back from a terminal position, retry later, edit credentials or reload after extension invalidation. Keep prior results visibly tied to their move when the board changes.

### Protect the player and the host page

- Restrict content scripts to the two supported chess origins. Justify `storage` for local settings and each exact Space host for inference. Replace the blanket `*.hf.space` grant with named defaults. Support an owner-operated compatible server through a configured HTTPS origin with narrowly granted access. Require explicit credential authorization for a new recipient. Keep token storage accessible only to trusted extension contexts. Exclude tokens from URLs, page content, logs, cache keys and evidence.
- Before the first request, disclose that the selected FEN and moves go to an unofficial third-party Space and may go to the named backup. Explain token transmission before saving it. Send only inference inputs, with no player names, game URLs, cookies, unrelated page text or analytics. Render external text through text nodes or an escape-first Markdown subset.
- Make all controls keyboard-operable, label the dialog and side choices, show focus, and restore it to the launcher on close. Announce meaningful status changes once. Keep elapsed seconds silent. Verify text contrast of 4.5:1 for normal text, 3:1 for large text and control indicators, a usable layout at 200% zoom, and static progress feedback with reduced motion.
- A closed panel may perform a cheap board-presence check. It performs zero full move-tree or piece scans while closed or hidden. Coalesce visible updates and read once more on Ask. Verify unchanged board bounds, usable replay controls, and one launcher after same-tab navigation. Keep inference confined to post-game review and independent analysis.

### Prove and package the release

- Give each routed fixture a distinct identity. Several current lichess fixtures share `/analysis`, so assert which DOM loaded before checking its payload. Compare complete expected FENs: the custom fixture supplies `… b - - 1 1`, while the current E2E expectation substitutes `… b - - 0 1`. Replay both real recordings against the **Black-to-move position after `3.Bc4`**. Use position-matched, clearly labeled synthetic replies for other cases. Assert the headline itself, transport abort, request count and fallback order. Save the report and screenshots for every visible state. Record the user’s dated live chess.com check with the selected move, expected position and extension version.
- Produce a versioned ZIP with `manifest.json` at its root and an explicit runtime file inventory. Exclude tests, docs, evidence, dependencies, repository metadata and credentials. Increment the manifest version for updates. Supply an original 128px Store icon, representative screenshots, accurate listing copy, support contact, reviewer instructions and a public privacy-policy URL. State one purpose: post-game chess explanation. Identify chess.com and lichess as supported sites and the Spaces as independent operators. Match dashboard permission justifications, remote-code declaration, data-use disclosures and retention statements to the shipped behavior. [Store privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy) · [Listing assets](https://developer.chrome.com/docs/webstore/images) · [Program policies](https://developer.chrome.com/docs/webstore/program-policies/policies)
- Document installation, both analysis modes, fallback limits, token removal, troubleshooting, test commands and release packaging. **Public-scale risk:** either unofficial ZeroGPU Space can throttle, change or disappear, and both can run out of capacity together. The extension must offer bounded failure, a useful recovery message and a configurable server. Before public launch, the owner should decide whether to coordinate expected traffic with the Space operators or deploy a compatible duplicate. Funding or operating that service is a launch decision outside the code score.
